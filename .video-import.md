# Bulk Video Import — operator checklist (Sprint E)

Live stack: **Vite + Vercel + Cloudflare R2 + Supabase**. Videos live on R2, not in git.

## One-command publish

```bash
# Always dry-run a big batch first
npm run publish -- "media/<folder>" --category "AI" --tags "Big Ass,POV" --dry-run

# Real run (idempotent — skips catalog + R2 hits)
npm run publish -- "media/<folder>" --category "AI" --tags "Big Ass,POV"

# Safe batching
npm run publish -- "media/<folder>" --category "AI" --limit 50

# Optional: skip posters if ffmpeg missing
npm run publish -- "media/<folder>" --category "AI" --no-posters
```

What it does: scan folder → skip already-published → upload to R2 in parallel →
optional JPEG posters → insert entries into `src/shared/catalog-videos.js`
(with `.bak` + post-write verify).

Then:

```bash
npm run publish:doctor   # structure + poster coverage
npm run build
git add -A && git commit -m "publish batch" && git push   # → Vercel prod
```

## Posters (card thumbs)

New publishes get posters automatically when `ffmpeg` is available.
Backfill missing:

```bash
npm run posters -- --dry-run
npm run posters -- --limit 100
npm run posters
```

## Hard rules

- Catalog `src` must match the R2 key (`../media/<rel>` ↔ `media/<rel>`).
- Match files by **full relative path**, never basename alone (collisions exist).
- Never commit raw `.mp4` — only catalog metadata + deploy.
- Re-run publish is safe: already-on-R2 / already-in-catalog are skipped.
- Live creator uploads use hashed numeric ids (`uuidToStableInt`) — never `Number(uuid)`.

## Google Drive / downloads

There is no Drive API in-repo. Typical flow:

1. Download / sync a folder from Drive into `media/<batch>/` on this machine.
2. Rename if needed (spaces OK; paths must stay stable once published).
3. Run `npm run publish` as above.

## Smoke after every batch

| Check | Command / action |
|--------|------------------|
| Catalog integrity | `npm run publish:doctor` |
| Build | `npm run build` |
| Live sample | Open a new id on prod, play + card poster |
| R2 object | Public URL `…r2.dev/media/<rel>` returns 200 |

## Recovery

- Catalog write failed → auto-restored from `catalog-videos.js.bak`; media may already be on R2 — re-run publish.
- Missing posters only → `npm run posters`.
- Wrong category/tags → edit catalog entries carefully or re-publish is **not** a rewrite tool; fix JSON fields by hand / small script.
